# MongoDB Features Reference & Viva Examination Guide

This document maps **every MongoDB and Mongoose feature** implemented in **PrepTrack**, detailing where it exists in the codebase, what it does, and the **most probable viva/oral exam questions with model answers**.

---

## 📊 Comprehensive Feature Mapping Table

| # | MongoDB / Mongoose Feature | Location in Code | One-Line Explanation | Likely Viva Question & Model Answer |
|---|---|---|---|---|
| 1 | **Database Connection & Lifecycle** | `server/config/db.js` (`connectDB`) | Manages connection pooling, handles connection retry and fatal failure termination. | **Q: What happens if MongoDB URI is invalid or connection drops?**<br>**A:** `mongoose.connect()` throws an error caught in the try/catch block. In `db.js`, we log an actionable diagnostic message and invoke `process.exit(1)` to prevent undefined server states. |
| 2 | **Schema Validation** | `server/models/User.js`, `Question.js`, `PrepItem.js` | Enforces strong data types, mandatory fields, string length constraints, and regex email validation. | **Q: Does MongoDB natively enforce schemas, or does Mongoose?**<br>**A:** MongoDB natively supports JSON Schema validation via collection validators, but Mongoose applies client-side application schema validation before sending BSON documents to the database engine. |
| 3 | **Enum Validation** | `server/models/Question.js` (`category`, `difficulty`), `Application.js` (`status`) | Restricts field values to an enumerated set of permitted strings. | **Q: What error does Mongoose throw if an unlisted enum string is passed?**<br>**A:** It throws a `ValidationError` with kind `enum`. Our `errorHandler.js` intercepts this and returns HTTP 400 Bad Request with a human-readable error message. |
| 4 | **Embedded Subdocuments & Arrays** | `server/models/Question.js` (`options`), `TestAttempt.js` (`answers`) | Stores 1-to-many child data (e.g. 4 options or array of test answers) within the parent document. | **Q: When should you embed documents instead of referencing them?**<br>**A:** Embed when child data has a 1-to-few relationship, is bounded in size (<16MB BSON limit), and is always read and updated atomically alongside the parent document (e.g. test options and submission answers). |
| 5 | **Document Referencing (Normalization)** | `server/models/TestAttempt.js` (`userId`, `answers.questionId`), `Application.js` (`userId`) | Stores `ObjectId` pointing to documents in another collection to avoid data duplication. | **Q: Why reference `userId` and `questionId` instead of embedding full user profiles or questions?**<br>**A:** Referencing avoids copying large question texts and user metadata redundantly across thousands of attempts, preserving single sources of truth. |
| 6 | **Document Population (`.populate()`)** | `server/controllers/testController.js` (`getTestAttemptById`) | Performs client-side join resolving `ObjectId` references to full documents in foreign collections. | **Q: How does Mongoose `.populate()` differ from MongoDB `$lookup`?**<br>**A:** `.populate()` performs separate secondary queries initiated by the Node.js Mongoose layer, whereas `$lookup` is an aggregation stage executed entirely inside the MongoDB database engine. |
| 7 | **Unique Index** | `server/models/User.js` (`email: 1, unique: true`) | Enforces database-level uniqueness across documents to prevent duplicate user registrations. | **Q: What MongoDB error code occurs on a duplicate key violation?**<br>**A:** MongoDB returns error code `11000` (`E11000 duplicate key error`). Handled in our `errorHandler.js` to return HTTP 409 Conflict. |
| 8 | **Compound Index** | `server/models/Question.js` (`category, topic, difficulty`), `TestAttempt.js` (`userId, createdAt: -1`) | Creates an index over multiple fields with specified sort directions for multi-predicate query optimization. | **Q: What is the Prefix Rule for Compound Indexes?**<br>**A:** A compound index on `{A: 1, B: 1, C: 1}` can support queries on `(A)`, `(A, B)`, and `(A, B, C)`, but CANNOT index queries filtering only on `(B)` or `(C)` without the leading prefix `A`. |
| 9 | **Text Index & Full-Text Search (`$text`)** | `server/models/Question.js` (`text: 'text', topic: 'text'`), `PrepItem.js` (`title: 'text', notes: 'text'`) | Builds an inverted keyword index to support linguistic keyword matching and search scoring. | **Q: How do you rank full-text search results by relevance?**<br>**A:** Use projection with `$meta: 'textScore'` and sort by `{ score: { $meta: 'textScore' } }` so the highest-scoring matching documents appear first. |
| 10 | **Aggregation: `$match`** | `server/controllers/statsController.js`, `testController.js` | Filters the document stream to pass only matching documents to the subsequent pipeline stages. | **Q: Why should `$match` ideally be placed at the very start of a pipeline?**<br>**A:** Early `$match` filters take advantage of indexes and drastically reduce the number of documents passed to memory-intensive downstream stages like `$group` and `$lookup`. |
| 11 | **Aggregation: `$sample`** | `server/controllers/testController.js` (`startTest`) | Randomly selects a specified number of documents using MongoDB's native pseudo-random sampling. | **Q: Why use `$sample` instead of fetching all documents and picking randomly in JavaScript?**<br>**A:** `$sample` selects documents directly inside the database kernel without serializing and transferring the entire collection over the network to Node.js, reducing latency and memory usage from O(N) to O(sampleSize). |
| 12 | **Aggregation: `$project`** | `server/controllers/testController.js`, `statsController.js` | Reshapes document structures, renames fields, computes derived properties, and excludes secret fields. | **Q: How does `$project` protect test integrity in PrepTrack?**<br>**A:** In `/api/tests/start`, `$project: { correctIndex: 0, explanation: 0 }` explicitly removes the answer key from the payload sent to the client browser. |
| 13 | **Aggregation: `$unwind`** | `server/controllers/statsController.js` (`getAccuracyByCategory`) | Deconstructs an array field from input documents to output a discrete document for each array element. | **Q: What does `$unwind` do to an array with 5 elements?**<br>**A:** It outputs 5 copies of the parent document, where each copy contains one individual element of the original array in place of the array itself. |
| 14 | **Aggregation: `$lookup`** | `server/controllers/statsController.js` (`getAccuracyByCategory`, `getWeakTopics`) | Executes a relational left outer join between collections (joining attempts' `answers.questionId` to `questions._id`). | **Q: What is the output data type of a `$lookup` stage?**<br>**A:** It always adds an **array** field to the document containing the matching records from the foreign collection (even if only 1 match exists). Usually followed by `$unwind`. |
| 15 | **Aggregation: `$group` & Accumulators** | `server/controllers/statsController.js` (`$sum`, `$first`, conditional sums) | Groups input documents by a specified identifier expression and computes aggregate metrics. | **Q: How do you conditionally count values in a `$group` stage?**<br>**A:** By combining `$sum` with `$cond`: `$sum: { $cond: [{ $eq: ["$answers.isCorrect", true] }, 1, 0] }`. |
| 16 | **Aggregation: `$dateToString`** | `server/controllers/statsController.js` (`getScoreTrend`) | Converts BSON Date objects to formatted string representations (e.g. `%b %d, %H:%M`) for charts. | **Q: Why format dates on MongoDB server instead of frontend?**<br>**A:** It standardizes time formatting, enables direct grouping by day/month/year inside MongoDB, and minimizes frontend rendering transformation overhead. |
| 17 | **Atomic Update Operators: `$inc`** | `server/controllers/testController.js` (`streak.current`), `prepController.js` (`revisionCount`) | Atomically increments numeric values in MongoDB without race conditions. | **Q: Why use `$inc` rather than reading the count in Node.js, incrementing by 1, and saving?**<br>**A:** Reading and saving causes concurrency race conditions when multiple requests arrive simultaneously. `$inc` executes atomically at the document level inside MongoDB engine lock. |
| 18 | **Atomic Update Operators: `$set`** | `server/controllers/testController.js`, `prepController.js` | Modifies or adds specific document fields without replacing the entire document. | **Q: What is the difference between `collection.replaceOne()` and `$set`?**<br>**A:** `replaceOne` overwrites the entire document, whereas `$set` updates only the specified target fields, preserving all other existing fields untouched. |
| 19 | **Bulk Insertion: `insertMany` (`ordered: false`)** | `server/seed/seedQuestions.js` | Inserts large batches of documents concurrently in a single round-trip. | **Q: What does `ordered: false` do during `insertMany`?**<br>**A:** If one document causes an error (e.g. duplicate key), MongoDB continues inserting all other remaining valid documents in the array rather than immediately aborting the entire batch. |
| 20 | **Cursor Pagination (`.skip()` and `.limit()`)** | `server/controllers/questionController.js`, `prepController.js`, `appController.js` | Returns paginated subsets of collections for responsive UI table and list views. | **Q: How do you calculate skip offset for page N with limit L?**<br>**A:** `skip = (page - 1) * limit`. |
| 21 | **Field Projection (`select: false` & `+password`)** | `server/models/User.js`, `server/controllers/authController.js` | Excludes sensitive fields (e.g. password hash) from queries by default, requiring explicit `+` opt-in. | **Q: Why use `select: false` on the User password field?**<br>**A:** It guarantees that queries like `User.find()` or `User.findById()` never accidentally leak hashed passwords to API consumers unless specifically overridden with `.select('+password')`. |
| 22 | **Mongoose Document Middleware (Pre-Save Hooks)** | `server/models/User.js` (bcrypt hash), `PrepItem.js` (revision schedule) | Intercepts document lifecycle events before persistence to execute business logic. | **Q: What is the function of `isModified('password')` in the User pre-save hook?**<br>**A:** It ensures the password hash is only recomputed when the user changes their password, preventing double-hashing on regular profile updates. |
| 23 | **Mongoose Virtuals** | `server/models/TestAttempt.js` (`virtual('accuracy')`) | Defines computed getters on documents that are evaluated dynamically and not persisted in BSON. | **Q: Why use a virtual for `accuracy` instead of saving it in the database?**<br>**A:** It eliminates data redundancy and prevents state desynchronization: accuracy is always strictly `(score / total) * 100` without consuming storage. |
| 24 | **Chatbot Memory & Conversation Persistence** | `server/models/ChatMessage.js`, `controllers/chatController.js` | Stores multi-turn user queries and AI mentor replies with chronological compound index `(userId, createdAt: 1)`. | **Q: How does PrepTrack store chat queries in MongoDB?**<br>**A:** We use a dedicated `ChatMessage` collection with `role` ('user' or 'assistant') referencing `userId`, indexed by `(userId, createdAt: 1)` to retrieve conversational context chronologically with `.limit(50)`. |
